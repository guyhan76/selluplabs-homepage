# 견적문의 직접 이메일 전송

사용자는 2026-10-10 이메일 앱 없이 직접 접수하고 비용 없는 방식을 선택해 달라고 요청했다. FormSubmit의 무료 폼 전송을 연결했다. 별도 회사 서버·유료 이메일 API·API 키는 사용하지 않는다. 문의 내용은 외부 서비스 FormSubmit을 거쳐 `lis000@hanmail.net`으로 전달된다. 서비스 정책과 이용 가능 여부는 공급사가 관리한다.

## 실제 수신 연결 (담당자 최초 1회)

1. 최신 Pages 배포 성공 후 `https://younghwa-package.pages.dev/mail-setup.html`을 연다.
2. 수신 이메일 활성화 요청을 누르고 FormSubmit 화면의 안내를 따른다. 일반 HTML POST로 첫 활성화를 진행하여 AJAX 전송 전 수신 주소를 확인한다.
3. `lis000@hanmail.net`의 받은메일함 또는 스팸함에서 FormSubmit 활성화 메일을 찾고 Activate Form을 누른다.
4. 홈페이지에서 실제 시험 문의 1건을 보내고 수신함에 들어온 회사명·연락처·문의 분야·제작 내용을 대조한다. 코드 배포나 공급사의 접수 응답만으로 실제 받은메일함 도착을 주장하지 않는다.

## 구현

- `quote-form.js`에서 고정된 수신 주소로 AJAX POST를 보낸다. 입력 검증, 중복 클릭 차단, 보내는 동안 언어/양식 잠금, 성공/거절/연결 오류 상태를 구분한다.
- 실패와 시간 초과에서는 입력을 유지하고 자동 재시도하지 않는다. 응답을 받기 전에 연결이 끊어지면 전송 여부가 불확실하므로 전화로 확인하도록 안내한다.
- 최초 활성화를 요구하는 응답은 고객 접수 성공으로 표시하지 않는다. 성공 응답도 ‘전송 요청 접수’로 표현하며 받은메일함 도착을 보장하지 않는다.
- JavaScript가 꺼져 있어도 HTML form의 POST로 FormSubmit에 전달할 수 있다. 서비스의 CAPTCHA/보안 검사는 끄지 않는다. honeypot 필드도 둔다.
- FormSubmit의 외부 폼 처리 사실을 양식에 표시한다. 향후 별도 개인정보 처리방침과 보유 기간 등 회사의 실제 운영 정책이 정해지면 반영한다.
- Google/Naver 확인 태그와 Google HTML 확인 파일은 유지한다. 셀업랩스 메인 홈페이지의 기존 문의 기능은 변경하지 않는다.

## 검증 범위

자동 브라우저 검사는 외부 전송 요청을 가로채 모의 응답으로 검증한다. 실제 고객 데이터나 시험 메일을 공급사로 전송하지 않는다. 이 개발 환경은 formsubmit.co에 대한 외부 접속이 제한되어 현재 공급사 응답과 실제 메일 수신은 확인하지 못했다. 위 활성화와 실제 수신 확인은 필요하다.

검증 결과: TypeScript/Vite 빌드 및 독립 Pages 빌드 통과. `tests/younghwa-enquiry.spec.ts` PC·모바일 6개 통과. 수신 주소 고정·중복 요청 방지·전송 대기·거절/활성화/통신 오류·입력 보존·언어 전환·320px 화면을 모의 응답으로 확인했다. 실제 발송/수신 성공을 의미하지 않는다.
